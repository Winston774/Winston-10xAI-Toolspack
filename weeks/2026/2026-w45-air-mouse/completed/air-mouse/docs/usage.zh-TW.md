# 使用指南

[返回首頁](../README.md)

## 安裝與第一次啟動

從 [Releases](https://github.com/Winston774/air-mouse/releases/latest) 下載 arm64 壓縮檔，解壓縮後將 `Air Mouse.app` 放進「應用程式」。如需核對下載檔，將同一版的 `SHA256SUMS.txt` 與 ZIP 放在同一資料夾，於該資料夾執行：

```sh
shasum -a 256 -c SHA256SUMS.txt
```

公開版本使用 ad-hoc 簽章，尚未經 Apple 公證。若首次開啟因開發者無法驗證而遭阻擋，確認來源後，到「系統設定 → 隱私權與安全性 → 安全性」選「仍要打開」，再依畫面確認。這項操作只針對該 App；不需要全域停用 Gatekeeper。步驟依 [Apple 說明](https://support.apple.com/en-gb/102445)。

App 啟動後會出現在選單列，不會出現在 Dock。找不到圖示時，可再次開啟 App 來顯示校正視窗。

## 權限與 AirPods 設定

| 權限 | 用途 | 設定位置 |
| --- | --- | --- |
| 動作與健身 | 取得耳機動作資料 | 系統設定 → 隱私權與安全性 → 動作與健身 |
| 藍牙 | 尋找已配對的 AirPods、嘗試重連 | 系統設定 → 隱私權與安全性 → 藍牙 |
| 輔助使用 | 發送游標移動與滑鼠點擊 | 系統設定 → 隱私權與安全性 → 輔助使用 |

權限項目通常會在 App 首次請求後出現。更新或自行重建後若無法控制游標，請重新檢查輔助使用授權。App 不要求麥克風、相機或螢幕錄製權限。

先將 AirPods 與 Mac 配對並連線，在 AirPods 設定中關閉「自動耳朵偵測」。兩耳都放回充電盒，保持盒蓋打開，再等待選單顯示來源耳與資料頻率。單獨出現「已連線」不能代表已有新動作資料。

## 校正方向

收到未校正來源耳的資料時，App 會提示校正；也能隨時從選單選「校正方向…」。

1. 像拿遙控器一樣持握，讓盒子前端朝螢幕。
2. 按「開始校正」，拿穩約 1.5 秒。
3. 依提示把前端向上抬約 30°，然後停住。這一步盡量維持單純上下抬動。
4. 完成後，以相同握法左右轉、上下抬，確認游標方向。

動作串流每次由一耳提供，左右耳在盒內的座標方向不同，需要各自校正。來源換成另一耳時，若尚無校正結果會再提示。校正期間換耳，流程會重新開始；成功結果保存在本機。目前校正依左／右來源保存，沒有按實體裝置分組，換另一副耳機後請重新校正兩耳。

若上下方向不符合習慣，可切換「上下反轉」。換了持握方向或校正不準時，重新執行「校正方向…」。

## 移動、點擊與暫停

| 動作 | 結果 |
| --- | --- |
| 左右轉盒子 | 左右移動游標 |
| 前端上下抬 | 上下移動游標 |
| 停穩後輕敲一下 | 左鍵 |
| 快速輕敲兩下 | 雙擊 |
| `Control + Option + M`（`⌃⌥M`） | 暫停／恢復游標控制 |

點擊前先停止移動；較輕的點按需要短暫靜止。點按偵測會排除部分揮動及敲擊回彈，也會把游標帶回點按前的記錄位置，降低敲擊造成的偏移。力道過輕、持握不同或移動中敲擊都可能漏判。

「游標速度」有慢／中／快三段。細部操作先用慢速，再按習慣調整。右鍵、捲動與獨立拖放手勢尚未提供。

暫停後仍會收集動作與寫入記錄，且仍可能重新訂閱動作串流。暫停會禁止新的自動藍牙重連嘗試；已送出的連線請求可能仍會完成。若要完整停止，選單點「結束」。

## 點按校正測試

選單 →「點按校正測試…」。測試約一分鐘，期間停止 Air Mouse 的游標移動與點擊。

1. 拿穩不動 8 秒，量測持握晃動。
2. 綠點亮起時，用希望偵測到的最輕力道敲一下，共 10 次。
3. 綠點亮起時快速敲兩下，共 5 次。
4. 正常左右、上下移動盒子 15 秒，不要敲擊。

App 以這次樣本比較 0.06–0.50 g 的門檻，列出單擊、雙擊、多算與誤觸次數，優先降低誤觸，再給建議值。按「套用」才會保存門檻。建議值反映這次測試，無法保證之後所有握法都準確；持握或力道改變時可再測一次。

測試期間請確認資料持續到達、選單 Hz 正常。中途斷線或樣本不足時仍可能出現建議值，請重新完成整輪測試。表格中的雙擊結果是本輪樣本重算的偵測結果，未驗證 macOS 或目標 App 實際接收雙擊的成功率。

也可選擇預設靈敏度：低 0.40 g、中 0.30 g、高 0.16 g。數值越小越容易抓到輕敲，同時可能增加誤觸。可隨時取消「點按盒子＝左鍵」保留移動功能。

## 斷線與自動重連

沒有新動作輸入超過約 0.15 秒時，游標驅動會停止移動；收到動作斷線通知時也會停止。恢復資料後仍須符合權限與方向校正條件才能正常使用。

「斷線時自動重新連線」預設開啟。App 在資料中斷超過 4 秒且動作服務回報未連線時，嘗試連到已配對、名稱包含 `AirPods` 的裝置。它優先採用之前記住的位址，否則使用最近存取的候選裝置。重試間隔會隨失敗次數增加，持續失敗後降至每分鐘一次；不保證每次成功。

把耳機交給 iPhone 或其他裝置使用前，先暫停游標控制或關閉自動重連，避免 Mac 主動重新連接。若裝置改名後不含 `AirPods`，自動重連可能找不到它，仍可在 macOS 藍牙設定手動連線。

## 記錄與命令列參數

預設資料夾為 `~/Library/Logs/AirPodsAirMouse`，可從選單「打開紀錄資料夾」進入。每次啟動產生 `airmouse-<時間>.jsonl`，內容與保存方式見[隱私說明](privacy.md)。

若從原始碼建置，可在專案根目錄執行：

```sh
# 指定記錄資料夾；請先結束正在執行的 App
open "AirMouse/build/Air Mouse.app" --args "$PWD/logs"

# 額外記錄逐筆感測資料；請先結束正在執行的 App
open "AirMouse/build/Air Mouse.app" --args "$PWD/logs" --raw

# 開啟點按校正測試；已在執行時也可使用
open -n "AirMouse/build/Air Mouse.app" --args --tap-test
```

記錄資料夾是第一個不以 `-` 開頭的參數。`--raw` 會增加大量資料，在歷史約 50 Hz 的串流下可接近每秒 50 行；部分流程會略過逐筆記錄。App 已在執行時，新啟動程序只會請既有程序顯示校正或測試視窗，無法藉此更改原本的記錄資料夾或 `--raw` 設定。

## 常見問題

| 情況 | 檢查方式 |
| --- | --- |
| 開啟後找不到主視窗 | 查看選單列；再次開啟 App 可顯示校正視窗 |
| 沒有動作資料 | 確認盒蓋打開、自動耳朵偵測關閉、AirPods 連到這台 Mac，並允許動作與健身 |
| 已連線但一直等待資料 | 結束其他使用耳機動作資料的 App；停止通話或 AirPods 麥克風使用，再觀察是否恢復 |
| 有 Hz 數值，游標不動 | 確認輔助使用權限、控制游標已開啟，且目前來源耳已完成校正 |
| 左右或上下方向奇怪 | 用一致的持握方向重新校正；檢查上下反轉設定 |
| 輕敲沒反應 | 先停穩，確認點按功能開啟，再執行點按校正測試 |
| 移動時容易誤點 | 提高 g 門檻、重新校正點按，或暫時關閉點按功能 |
| AirPods 被 Mac 重新連回 | 關閉自動重連、暫停控制，或結束 App |
| 合蓋後停止控制 | 重新開蓋；本版操作流程需要開蓋，合蓋可靠性尚未解決 |

回報問題時附上版本、Mac 晶片、macOS、AirPods 型號與韌體、是否開蓋、權限與自動耳朵偵測設定，以及最短重現步驟。需要附記錄時先檢查時間、裝置資訊與動作內容，詳見[貢獻指南](../CONTRIBUTING.md)。

## 移除與清除資料

先從選單「結束」，再將 `Air Mouse.app` 移到垃圾桶。記錄與偏好會保留；如需清除，可手動刪除記錄資料夾。若曾指定其他記錄路徑，也需自行處理。

關閉 App 後，可用下列命令清除本專案的校正與偏好設定，包括優先藍牙位址；不會刪除 macOS 中的 AirPods 配對：

```sh
defaults delete local.winston.airpods-air-mouse
```

也可在「系統設定 → 隱私權與安全性」撤銷相關權限。
