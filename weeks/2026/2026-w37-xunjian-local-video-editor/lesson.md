# 教學講義：讓 Agent 剪輯有可讀情境、可逆提案與可驗證證據

## 學習目標

完成本週後，你應能：

1. 解釋為何 Agent 需要先讀取精確專案版本與剪輯方向。
2. 把「偵測到問題」與「允許刪除內容」分成兩個決策。
3. 用版本化提案與一次復原，控制多步剪輯的風險。
4. 分辨結構檢查、抽樣證據、人工播放審閱各自代表的範圍。
5. 用精簡、分段的 MCP 呼叫保留 Token 給真正需要判斷的片段。

## 架構

```text
使用者 UI / Codex / Claude Code
          ↓
  stdio MCP（25 個工具）
          ↓
同一個 localhost Python 服務
  ├─ 專案、版本、時間軸與復原
  ├─ 背景工作與素材受管路徑
  ├─ 影格、音訊與短片證據
  └─ SQLite 本機資料
          ↓
FFmpeg / 本機 ASR / 本機瀏覽器工作台
```
MCP 沒有第二份剪輯資料庫；它連到正在運行的工作台。這讓人類 UI 和 Agent 面對相同的版本、提案與結果，也要求兩者都遵守同一個版本契約。

## WATE 剪輯閉環

```text
W — What happened：讀取 context、專案版本、選取區間與工作狀態
A — Analyze：只擷取需要的最多 30 秒區間證據，區分偵測和判斷
T — Take action：建立版本綁定提案，先審閱差異，再經人類確認套用
E — Evaluate：驗證結構、登錄實際審閱範圍、保留未知項目
```

對應的最小 Agent 工作流：

```text
editor_get_context
  → editor_inspect_range 或 editor_analyze_range
  → editor_prepare_edit
  → editor_get_edit
  → 人類確認
  → editor_apply_edit
  → editor_verify_edit
  → 必要時 editor_record_review
```

若 `expected_version` 或提案的 `base_version` 已過期，Agent 必須停止、重新讀取情境，再建新提案。這是避免「根據舊時間軸自動刪除新內容」的核心防線。

## Agent 分工

| 角色 | 只負責什麼 | 不該越界什麼 |
|---|---|---|
| Context Agent | 讀取專案、版本、播放頭、剪輯方向與未知資訊 | 猜測未開啟的專案或沿用舊版本 |
| Evidence Agent | 取得限定區間的影格、音訊、短片與字幕 | 宣稱抽樣代表整段影片 |
| Proposal Agent | 建立具體 operations、差異與副作用 | 直接改寫原始時間軸 |
| Reviewer | 比較前後版本，確認保留／刪除意圖 | 將模型輸出當作自動核准 |
| Apply Agent | 只套用已確認、版本相符的提案 | 跳過確認或容忍過期版本 |
| Verification Agent | 記錄結構結果與實際播放範圍 | 把未播放區間標成已驗收 |

這個拆法能讓每一步的輸入、輸出、責任人與失敗條件都可檢查；它也讓不同 Agent 或人類可以在同一份專案上接力，而不必把整條時間軸塞進單次對話。

## Token 成本控制

- `editor_get_context` 先取得摘要，不一次讀所有波形、縮圖或長逐字稿。
- `editor_inspect_range` 一次最多 30 秒、8 張影格；先縮小到需要判斷的切點。
- `editor_read_evidence` 預設回傳少量原生媒體區塊；需要額外檔案時再以 ID 明確選取。
- 長工作拿到 `job_id` 後以合理間隔查 `editor_job_status`，避免高頻輪詢。
- 提案僅保留操作、原因、版本與可檢查差異；不需要保存模型內部推理。
- 發生 stale 時直接回到 context，不把舊判斷硬套到新版本。

## 證據語意

| 證據 | 可以說明 | 不能說明 |
|---|---|---|
| 結構驗證 | 版本、時間軸、欄位、提案契約是否符合規則 | 口條是否自然、畫面語意是否正確 |
| 單張／多張抽樣影格 | 指定時間點看見的畫面 | 其間連續畫面已無問題 |
| 音訊片段 | 指定範圍可供人耳審閱 | 全片聽感或字幕內容都正確 |
| 人工審閱紀錄 | 記錄審閱者聲稱實際看過／聽過的範圍 | 未覆蓋區間的品質 |

把未知保留下來，會比用模糊的「已驗收」更有助於下次接力與修正。
