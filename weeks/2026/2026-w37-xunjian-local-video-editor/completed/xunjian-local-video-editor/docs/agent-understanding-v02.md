# v0.2：Agent 理解、提案與驗收

> **W37 歷史記錄註記**：本檔保留來源技術與舊驗收脈絡。它提到的 artifacts、模型、合成素材與成功結果沒有隨學員 ZIP 附上，也不構成本輪發布證據；請以[W37 驗證紀錄](../../../docs/verification.md)確認本輪實際執行與未知範圍。

本次依 2026-09-08 使用者提供的實際剪輯回報補足資訊接口。目標是讓每項剪輯判斷能取得正式證據、每項修改能檢查結果，並明確保留未知。

## Workflow 與責任

```text
使用者 UI ／ Agent stdio MCP（25 tools）
    ↓
情境與剪輯方向 → 區間觀察 → 分析候選
    ↓
持久化 before／after 提案 → 合成預覽 → 精確版本整批套用
    ↓
結構／字幕檢查 → 指定檔案視聽審閱 → 記錄範圍與未確認事項
```

拾剪處理時間換算、媒體擷取、可重現合成、快取、原子修改及檢查。Agent 解讀原生圖像／音訊、使用者目標及敘事價值；不能把低音量或低畫面變化直接當成可刪除理由。

| 模組 | 主要責任 |

| `core.py` | SQLite 專案、穩定 ID、字幕對齊狀態、brief、提案前後快照、原子套用與復原 |

| `web/agent-workspace.js` | 剪輯方向、選取區間、聲畫證據、前後提案、局部字幕複核與驗證介面 |

## 接口的確定性

- 情境由每個 UI 分頁獨立回報，具有 client ID、序號、焦點、播放頭、選取項目與區間。閒置仍有 heartbeat，超過 60 秒視為過期；重啟不冒認先前分頁仍在工作。
- 首次呼叫 `editor_get_context` 即可取得目前版本、brief、可用能力及缺少的分析。無即時 UI 或多分頁歧義會明示，可指定 project/client ID。
- `brief` 包含目標、觀眾、節奏、目標秒數、必須保留內容及補充說明，與專案一起版本化；空白代表尚未取得方向。
- 字幕、單詞、映射後字幕與切點均有穩定 ID。文字／時間修改導致逐字資料失效時回傳 warnings；`valid` 表示結構有效，辨識正確度需另審。
- 批次提案保存精確 before／after 快照。預覽生成的片段 ID 與最終套用一致；失敗、過期或重複套用不產生部分寫入。全部操作僅佔一步復原。
- `base_version` 是可寫入的目前版本；提案 after 的 `snapshot_version` 是尚未套用的預計版本，不能拿它修改已保存專案。`edit_id` 與 `preview_side` 明確識別預覽側。

## 聲畫與驗證邊界

來源證據直接擷取素材；時間軸證據使用與正式匯出同一個合成器。先以專案尺寸完成字幕、標題、圖層及淡變，再縮小 JPEG。局部合成保留片段內原淡入淡出進度，並直接求素材交集；不必先渲染前面整段長片。

每次最多 30 秒、8 張 JPEG；另可取得 16 kHz 單聲道 WAV 與短 MP4。`editor_read_evidence` 直接回傳 MCP `image`／`audio` 內容，影片以 `resource_link`／`resources/read` 取得。公開接口提供已登錄的不透明證據 ID、URL 與資源 URI，無需找到素材路徑或自行擷取媒體。

低音量分析使用 20 ms RMS；畫面變化採 2 fps、160×90 灰階差異。這些訊號有取樣限制，無法判定游標操作、示範價值或是否應刪片。重錄文字候選查閱所選區間前後各 180 秒的同一時間空間字幕，至少一個字幕必須落在觀察範圍內；每次最多 1,000 個字幕、每句比較後續 40 句、最多 200 個候選，截斷會明示。`outside_observation_ranges` 列出需另外取得聲畫證據的位置；語意冗長與重錄最佳版本仍需 Agent 根據前後文及證據判斷。

驗證分四層呈現：

1. 結構：來源範圍、時長、ID、主影片空隙與切點。
2. 字幕：對齊缺失／失效、詞被切入、行數與邊界估算。
3. 證據：哪些影格、音訊及短片已生成，屬哪個版本與提案側。
4. 審閱：誰明確記錄看過哪些檔案、完成哪些檢查、具體結論。影格審閱只算該抽樣時間；音訊與影片才記錄連續區間。聲音／畫面／字幕版面彼此獨立。

任何已生成或已送出媒體都不會自動變成審閱通過。來源影格無法認證時間軸字幕版面；無音影片無法認證聽感；before 審閱不計入 after；套用後的新版仍需取得新版證據。

## Token 與成本

- 專案列表與 mutation 預設摘要，保留副作用及復原憑據；不把影片 bytes 或完整波形放進文字上下文。
- 區間逐字稿與影格按需讀取；`editor_read_evidence` 預設最多 3 張影格及 1 段音訊，回報省略項目。
- 證據依快照、操作與參數雜湊快取，重啟可重用，缺檔重新生成；專案版本變動不重用舊證據。目前為快照級快取，素材級增量失效屬後續工作。
- `editor_job_status(wait_ms=20000)` 支援有限等待，減少忙碌輪詢。
- `editor_get_edit` 提供差異，原子批次避免逐項修改反覆傳回整份專案。

## 本機驗收證據

2026-09-08 最終完整 Python 回歸 **110 項通過、0 失敗、0 跳過，36.702 秒**，包含審閱覆蓋與跨區間重錄修正。前端既有 **6 項測試通過**，新增模組語法與匯入檢查通過。完整紀錄：`artifacts/verification/automated-tests-v02.log`；摘要：`artifacts/verification/automated-tests-v02.json`。

- 真 FFmpeg：局部預覽與完整輸出像素差及音訊 RMS 淡變一致；時間軸第 601 秒直接渲染 1 秒區間；原有影片、圖片、疊加、字幕、變速與混音回歸通過。
- 真本機 ASR：原字幕「我們使用繁體中聞剪輯影片。」取得「我們使用繁體中文剪輯影片。」候選，10 詞含 ID 與辨識機率，原文保持不變。證據：`artifacts/verification/evidence-v2-asr.json`。
- UI：舊專案正常開啟；在合成示範保存 brief、重載確認持久化、取得 0–6 秒合成影格／音訊／短片、只登錄兩張實際檢視的畫面，驗證報告顯示部分審閱，沒有宣稱聽感通過。
- 最終服務重載後：UI 保存目標秒數為 17，重新開啟仍為 v7／17 秒；另外只登錄 0.733 秒的一張影格。正式 MCP 驗證回傳 `sampled_frames` 一筆、`reviewed_ranges=[]`、`checks=[visual]`，其餘聲畫保持未知。
- MCP：真實 stdio／HTTP 完成 25 工具探索、原生 image／audio、影片資源讀取、版本衝突、前後預覽隔離及原子套用。
- 獨立 Agent：未讀產品原始碼、資料庫或瀏覽器 DOM，以通用 stdio 測試 host 完成正式工具流程。詳見 `artifacts/verification/mcp-blind-acceptance.md`。該測試 host 只轉送 MCP 協定，不包含媒體擷取或剪輯邏輯；正常操作直接連接 Codex／Claude Code MCP 即可。
- 獨立流程將合成素材從 6 秒剪成 5.4 秒，並完成前後證據審閱、套用、驗證及復原回 6 秒。原專案「測試」維持 v71，內容逐欄比對未改動。

測試模型不支援音訊輸入，因此音檔成功交付仍未驗證聽感；這項限制沒有被掩蓋為通過。完整長篇實際口播品質、逐切點全程聆聽及語意敘事效果未在本輪宣稱完成。
