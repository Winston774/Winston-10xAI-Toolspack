# W38 講義：把參考短片讀成可交接的製作理解

## 先掌握一個例子

假設排名短片在主持人第二次說到「第一名」時，把頭像移到榜單頂列。只記「7 秒出現卡片」，改寫台詞後容易失去同步。更有用的交接包含：

- 原片約 6.8–7.4 秒可回看；時間精度先標為估計。
- 觸發點是第二次說到「第一名」，卡片在評價句結束後停止。
- 舊排名留在畫面上，新項目加入時維持累積狀態。
- 重製時依新台詞重新取得時間，保留揭露與排名更新的關係。

這是教學假設，沒有對應的真實影片或檢視證據。練習時請用自己的原片查證每項描述。

## 1. 準備來源與工作區（20 分鐘）

請 Agent 確認影片可讀取、記錄 SHA-256、時長、顯示尺寸、音軌，並建立獨立分析資料夾。source clock 以第一張解碼視訊影格為零點；容器起始時間、WAV 局部時間可能不同。

```text
請確認影片來源與輸出位置，先檢查本機工具是否可用。
建立 analysis/<影片名稱>/，保存來源與時間座標。
保持原片不變；目前沒有改編目標。
```

來源如為 URL，先確認可取得方式與授權。附帶 helper 只讀本機檔案。

## 2. 先讀整體，再找需要補看的地方（35 分鐘）

跟完整片，寫下形式、核心訊息、可能受眾、開場如何建立期待、資訊如何增加、注意力如何轉移、最後如何收束。吸引力與觀眾作用寫成推論；實際觀看數或轉換成效需要另外的資料。

概覽幀用於導航。依問題選擇播放或更密集的幀序列，優先檢查首尾、切點兩側、快閃文字、重要動作、字幕首次出現、音效與畫面交接。

```text
先建立全片敘事與時間地圖。
列出最需要補看的三個區段、各自要回答的問題，再決定補看密度。
請回報實際看過的範圍，以及抽樣間仍可能漏掉的事件。
```

## 3. 沿時間與系統各讀一次（40 分鐘）

第一輪由片頭到片尾看事件；第二輪追蹤每個重要系統的生命週期。

| 系統 | 主要問題 |
| --- | --- |
| A-roll／B-roll | 誰承擔主要敘事？插入畫面支援哪段話？何時返回主畫面？ |
| Caption／Typography | 哪些是說話字幕？哪些是獨立標題？如何斷句與強調？ |
| MG／UI | 卡片、榜單、介面是否跨鏡頭持續？哪些物件累積或替換？ |
| Effect | 運動、遮罩、閃光或轉場由什麼事件觸發？ |
| Audio | 人聲、配樂、環境聲、音效如何重疊、停頓與交接？ |

每個系統至少描述內容／樣式、位置與遮擋、進場、持續／更新、退場、敘事作用。區分物理場景、攝影機構圖與後製疊加。無法確定原作者的字體、器材、模型或參數時保留未知。

## 4. 把觀察接到製作需求（35 分鐘）

主文件與索引共用事件、系統、證據、素材 ID。每個重要事件分成：

1. `observed`：實際看見／聽到的行為。
2. `interpretation`：對注意力或敘事作用的解釋。
3. `generation_brief`：下一階段的製作需求與建議。

每項素材需求連回事件：主體、場景、動作、起終狀態、鏡頭裁切、字幕留白、人物／道具一致性、獨立圖文，以及所依賴的其他素材。

```text
請整理素材需求與依賴，並為重要事件同時記錄原片時間與語義錨點。
將固定關係、可替換內容、改動後需要重算的項目分開。
尚未指定新人物、產品或腳本，請保留待定欄位。
```

## 5. 驗證與接手（30 分鐘）

請 Agent 執行：

```text
python <SKILL_DIR>/scripts/validate_analysis.py <analysis-dir>/analysis.json --source <input.mp4>
```

驗證器檢查結構、時間、引用、證據路徑、依賴與交接狀態；`--source` 另核對原片 hash。它無法證明實際觀看、聆聽或語義正確。

接著人工或由具備視聽能力的 Agent 核對：

- 文件是否能從片頭一路讀到片尾？
- 證據是否足以支持重要文字、動作、聲音與同步判斷？
- 圖片抽取、WAV 產生、ASR 完成各自與實際檢視分開記錄了嗎？
- 缺口是否寫入 `unknowns` 和 `PROGRESS.md`？
- 下一位 Agent 知道先補看哪段、先準備哪個素材嗎？

保留 `partial` 是可續跑的交付方式。達到技能契約的完整覆蓋與交接條件後，再標示 `ready`。

## 本週繳交

提交主文件、索引、驗證結果，以及一句「我從這支片學到哪個可保留的製作關係」。證據先存放在自己的工作區；對外分享時只附你有權分享的內容。

評量依據：來源可核對、觀察與推論清楚、系統與事件有關聯、時間一致、未知項誠實、接手步驟可執行。僅有風格形容詞或大量抽圖，尚不足以完成本週任務。
