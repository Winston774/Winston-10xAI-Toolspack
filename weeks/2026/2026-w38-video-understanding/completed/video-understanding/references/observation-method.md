# 如何把影片讀成可重製的理解

本頁是由 Hypit 的參考影片閱讀與製作方法整理的操作方法；來源與轉換差異見 `hypit-method.md`。這裡的分層、ID 與交接狀態是本技能新增的契約。

## 1. 先建立一個會被修正的整體假說

跟完整支片的敘事發展，記下開場承諾、衝突／問題、資訊如何增加、什麼時候改變觀看焦點、揭露與結尾。依實際內容選擇段落，無須硬套每支片都有 CTA。

例如排名影片：人物講出名字 → 頭像加入榜單 → 評價落定時移入等級 → 音效強化判斷。真正可重用的關係包括「引入人物」「建立期待」「公布結果」「累積狀態」；只記每秒出現什麼圖片會漏掉榜單如何累積。

影片形式可能是口播、訪談、排名、示範、敘事短劇或純動態圖文。形式只是找問題的起點。把「影片試圖讓觀眾相信／感到／做什麼」寫成推論，不能由影片本身推導實際觀看數、轉換率或爆紅原因。

## 2. 同一時間軸上看不同層

| 功能 | 要辨識的內容 |
| --- | --- |
| A-roll | 承擔主要語義／表演的人聲或演出，可能只有聲音或位於小視窗 |
| B-roll | 插入的例子、證據、情緒或情境；覆蓋哪一段論述，何時返回主畫面 |
| Caption | 實際說話的顯示、斷句、強調、說話者配色、逐詞／逐句切換 |
| Typography | 獨立標題、論點、標籤、CTA，與口語不同的文字 |
| MG/UI | 榜單、卡片、裝置、資料圖、進度、介面；持續背景與新增物件的關係 |
| Effect | 畫面震動、閃光、變色、遮罩、景深或轉場，服務哪個事件 |
| Audio | 人聲、音樂、環境聲、事件音效及其重疊、停頓與尾音 |

一張合成畫面不會揭露原始工程檔的圖層。區分「可見的層次關係」與「建議的實作拆分」。同樣不要由視覺猜測原作者使用的模型、剪輯軟體或確切 CSS。

## 3. 由概覽追到關鍵瞬間

先取可讀的概覽幀，短片可從約每秒一張開始。這只提供導航，抽樣間的事件仍未知。優先補看：

- 首尾、切鏡兩側、話題或說話者切換；
- 每種字幕配置與強調方式的首次出現及變化；
- 短暫文字、遮擋、物件新增／替換／消失；
- 比較、動作、產品使用、重要螢幕文字與最後揭露；
- 同一系統跨切鏡後是否維持狀態，前景交接是否露出底層；
- 音效起點、聲畫不同步、音樂換段、人聲與畫面不同時切換。

對進出場可先縮到 0.1 秒左右的間距；若變化仍無法解釋，繼續縮小或查看原速／逐幀播放。用實際影格 PTS 判斷 VFR 影片，勿以平均 FPS 算出虛假的精確切點。幀圖標的是某個取樣瞬間，無法證明鄰近時間都一樣。

若只能取得靜態幀，不可宣稱聽過配樂、確認唇形同步或理解快於抽樣間距的動態。連續密幀能支持某段可見運動的閱讀，仍應列出抽樣間距及瞬時事件可能遺漏。

## 4. 每個重要系統要有生命週期

用穩定 ID，例如 `SYS-board`、`SYS-caption-host`。追蹤：

1. **內容與外觀**：哪些精確文字／數字、圖案、顏色、材質、字重、描邊與層次。
2. **空間**：位於哪裡、佔多少畫布、與人物／產品有何關係、誰遮住誰。
3. **進場**：何事觸發、從哪裡來、如何改變位置／縮放／透明度。
4. **活躍與持續**：停多久、是否累積、是否跨鏡頭持續、內容是否在固定容器內移動。
5. **變化與交接**：新增、替換、排序、遮蓋、狀態更新，舊內容與新內容有無重疊／空隙。
6. **退場**：觸發事件、方向、時長、下一個系統如何接手。
7. **觀眾作用**：建立人物、引導注意、比較、累積證據、放大反應或完成論述。

「彈入」僅是分類；重製所需的描述可包含由約 80% 放大至約 108% 再回到 100%、方向、持續範圍與哪個語義事件同步。無法量測時標估計範圍，勿填看似精確的貝茲曲線或毫秒值。

## 5. 三種空間各自描述

- **物理場景**：人物、產品、道具與環境；視線、接觸與真實互動。
- **鏡頭構圖**：視角、景別、主體位置、距離、裁切、可見身體範圍、鏡頭運動。
- **後製合成**：字幕、卡片、榜單、遮罩、分割畫面、疊加與 Z 次序。

版面可用正規化座標 `[x, y, width, height]`，原點為顯示畫面左上、數值 0–1；記錄依據與誤差。旋轉 metadata、pixel aspect 與 display aspect 都可能影響實際畫面尺寸。

生成素材 brief 應給主體留出字幕／榜單的預定空間。圖文屬於後製時，在建議中將其保留為獨立可編輯元素；不要把榜單文字誤當人物身處場景中的實體招牌。真正出現在場景中的招牌則保留其角色。

## 6. 文字與聲音保留各自證據

逐字稿記工具版本、語言、時間精度、音訊偏移、未辨識內容與校訂。中文用完整片語閱讀，字級對齊僅用來定位。混語人名、產品名與縮寫可由畫面和上下文核對；若發音沒有聽清楚，保留不確定。

把畫面 Caption、獨立標題、介面文字與說話內容分開記錄。字幕有縮寫／漏字時保留差異，畫面文字不自動當作說出的台詞。

聆聽時分人聲、音樂、環境與音效：情緒、節奏、起終時間、淡入淡出、是否壓低配樂、與畫面事件的關係。BPM、LUFS、音量差若未量測就用質性描述。音軌存在、WAV 已抽出、ASR 完成，都不等於聆聽完成。

音訊局部裁切的時間可能從 0 重啟。依 manifest 的音訊 segments／offset 映射回 source clock，不能直接把局部 ASR 秒數當原片秒數。

## 7. 用來源時間與語義事件雙重定位

例如 `EV-verdict`：

```text
source：6.8–7.4 秒，精度 estimated（仍待 0.05 秒序列確認）
anchor：第 2 次說到「第一名」時開始；評價句結束後卡片停止移動
observed：頭像移到榜單頂列；舊的兩個項目仍在；短促聲音與落定近似同步
interpretation：結果揭露，同時保留前面排名供比較
evidence：FRAME-68、CLIP-verdict、AUDIO-verdict
target relation：綁定新台詞的排名宣判，重新取得對齊時間
```

這是方法示意，不能當作任何輸入影片的真實分析。沒有台詞時，以動作、接觸、狀態改變等事件命名；純時鐘動態則明記 clock anchor。

## 8. 素材拆分由可觀察的角色決定

建立素材清單時問：下一階段必須產出什麼才能表達這個事件？

- 人物主表演：身份特徵、語氣、肢體、鏡頭、場景、留白；
- 反打與多視角：視線、位置、道具、光線與同一人物的一致性；
- 插入鏡頭／操作：必要動作、完整可辨識結果、源長度、銜接狀態；
- 實際產品或 UI：精確外觀、文字、數值與操作證據的來源；
- 圖形／字幕：內容規則、容器、樣式、狀態機、觸發事件；
- 聲音：配音、音樂、環境、音效各自的功能與同步需求。

記錄依賴圖：例如人物外觀基準 → 主表演／反打，已接受的配音 → 語義對齊 → 字幕與揭露事件。依賴用淺層、有用途的關係表達；不要平白增加多輪生成中間圖。

最後做兩次閱讀：從開頭走到結尾，檢查每段的視聽與含義是否能理解；再沿每個系統追蹤生命週期，找跨鏡頭遺漏、身份不連續和未交代的持續狀態。
