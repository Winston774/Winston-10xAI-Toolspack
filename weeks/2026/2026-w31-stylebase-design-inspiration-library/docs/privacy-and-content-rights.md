# 資料、隱私與圖片權利

## 資料留在哪裡

| 資料 | 預設位置 | 是否進入 Git |
|---|---|---|
| 原始圖片 | `library/inbox/` | 否 |
| SQLite 與分析結果 | `data/` | 否 |
| 本機設定 | `.env` | 否 |
| 程式碼與文件 | Repository | 是 |

## 何時會傳送圖片

- 匯入：不傳送。
- 重新掃描：不傳送。
- 搜尋與篩選：不傳送。
- 人工編輯：不傳送。
- 按下「送交 Codex」：選取的圖片會傳至 Codex 服務進行分析。

Stylebase 使用本機已登入的 Codex CLI，不在前端、SQLite 或 `.env` 保存 OpenAI API Key。Codex 帳號資格、用量、資料處理與保留方式受使用者自己的方案及適用條款約束。

## 不應送交的內容

- 密碼、金鑰、身份證件、付款資訊。
- 醫療、財務、人事或其他敏感個資。
- 客戶未公開設計、公司機密或 NDA 內容。
- 沒有權利上傳到第三方服務的圖片。
- 可能造成安全或法律風險的素材。

## 圖片權利

MIT License 只授權本 Repository 的程式碼與文件，不會改變使用者匯入圖片的權利。

收集設計參考時至少記錄：

- 原始網址。
- 作者／工作室／品牌。
- 收集日期。
- 已知授權或用途限制。
- 你的使用目的，例如「研究資訊層級，不重用原始圖像」。

AI 不應用來猜測授權狀態。若不確定，保留「待確認」，不要公開散布或直接用於商業作品。

## 開源維護者檢查

發行前執行：

```powershell
npm.cmd run validate:release
git status --short
git ls-files
```

確認清單：

- [ ] `data/` 沒有被追蹤。
- [ ] `library/inbox` 只有 `.gitkeep`。
- [ ] 沒有 `.env`、Token、SQLite、Log 或私人路徑。
- [ ] README 與成果截圖沒有機密內容。
- [ ] 示範圖片有明確的公開權利。

若曾經把敏感資料 commit，即使後來刪除，仍可能存在 Git 歷史；應立即撤銷憑證、停止推送，並依 GitHub 的敏感資料移除流程處理。
