# 本週講義｜從來源證據到原音影片

## 任務與準備

選一份你有權使用的訪談、演講或教學內容。練習以原音答案為中心，完成一份可以交接的剪輯企劃；進階再做一支 1920×1080、30 fps 的影片。長度、題數與用途由你設定。先讀 [README](README.md) 選路徑，準備來源資訊與完整逐字稿；沒有影音時只交付文字層分析，視聽欄位留待驗。

## 第一階段：來源與候選

1. 以 [quickstart](completed/source-led-video/references/quickstart.md) 初始化全新的 episode，避免把練習輸出放進技能目錄。
2. 填寫 `sources.json`，記錄來源標題、作者、日期、路徑與實測片長；在 `research/` 保存全片主題分布、依據及限制。
3. 定義受眾、要回答的問題和候選切點，填寫 `questions.json`、`candidates.json`。逐段檢查句子是否完整、前後文是否保留、主張是否忠於來源。
4. 執行 `score`。三項門檻任一為 `false` 或未知時，不能靠高分取得正式資格。八項分數有缺漏時，總分保留 `null`，區間只代表現有資訊的上下界。

**自問：** 看過字幕能支持哪些判斷？哪些仍需聽聲音、看表情或檢查畫面？理由須引用實際原句與時間證據，避免用「很精彩」代替判斷。

## 第二階段：首題與編排

1. 以 `plan` 建立空白 rundown 骨架，再填寫原音、opening、bridge、outro。
2. 在 `opening-selection.json` 比較所有問題的承諾吻合度、中心性、理解價值、答案強度與進場清晰度，選出首題並記錄理由。
3. 檢查第一段實質原音及導讀是否對應選中的問題；標題與縮圖的承諾須能在答案中得到支持。
4. 寫出 `narration-plan.json`：交代人物、主題、此刻談論的原因。日期與身分須查證；單人演講使用 solo 情境，不虛構主持人或來賓。

企劃路徑可在這裡交付：來源表、候選及評分、全題首題比較、rundown、旁白草稿、縮圖 brief 與待確認清單。未產生 WAV 時勿執行 `resolve`，也勿把估計時長當成實測。

## 第三階段：聲音、字幕與工程

1. 自行準備 [環境依賴](completed/source-led-video/references/dependencies.md)，用 `doctor` 確認路徑與套件。這只證明可找到依賴，還需要實際執行。
2. 核准每段旁白，按照 rundown 次序以兩個換行串接為 `voice/approved-narration.txt`。`check_narration.py` 會比對真正錄製／送 TTS 的文字；技能不包含 TTS。
3. 聽過最終 WAV 後記錄專名發音範圍及檔案 hash。聲音改過就重聽；自填核聽紀錄的真實性仍由審閱者負責。
4. 執行 `cut`；來源片段保留原音與正常速度。依最終 WAV 編排字幕及 `card_beats`，依原片秒數編排來源字幕與 markers。
5. 每段原音都寫 marker review：需要標記則附語義證據，不需標記則以 `keep_source` 說明理由，避免為了固定數量塞動畫。
6. `resolve` → `check` → `build_film.py`，產出 HTML 工程。再依原始 quickstart 的版本基準進行瀏覽器檢查與渲染；生成工程尚不等於已輸出 MP4。
7. 抽查代表影格並連續觀看／核聽最終影片，完成縮圖、標題、來源說明及 QA。保留未驗項目，勿把自動檢查當成人工驗收。

## 成果證據與通過標準

| 證據 | 通過標準 |
|---|---|
| 全片閱讀與候選表 | 附來源與時間；缺證據明示，語義三門檻不能以分數覆蓋 |
| 首題比較與 rundown | 全題比較可回查；第一段答案支持標題承諾 |
| 旁白核對（建片路徑） | 核准文本一致；專名核聽綁定目前 WAV；人物與日期有依據 |
| 工程與成片（建片路徑） | 實測時長符合自己要求；字幕、畫面回復、動畫、音畫均經實際檢查 |
| 交付限制 | 清楚列出已驗、未驗與權利範圍，不洩漏本機路徑或私人素材 |

## 失敗時的重試路徑

選段不完整：回到原片延伸切點或換候選。分數未知：補證據，保留未知直到核對完成。旁白不一致：先修核准文本，再更新 WAV／字幕與核聽紀錄。工程過期：重新 `resolve` 後建片；原片有改動時還須重新切片。詳細錯誤處理見 [疑難排解](docs/troubleshooting.md)。

分享練習成果只需提供你有權公開的短片／企劃摘要、候選取捨理由與未完成項目；金鑰、完整私有逐字稿和環境設定請留在本機。
