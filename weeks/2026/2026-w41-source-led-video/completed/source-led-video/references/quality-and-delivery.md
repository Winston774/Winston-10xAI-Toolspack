# 品質檢查、修訂與交付

驗收分成語意、技術與實際視聽三層。每層保留證據與未完成項目；某一層通過不代表其他層已完成。工具能檢查資料關係和媒體結構，觀眾能否理解仍須實際觀看。

## 語意與編輯

- 全片主題分布已理解；選段沒有只挑到脫離前情的金句。
- 每個來源候選的完整意思、語境保留、主張忠實三項 gate 有證據。
- 每一題都有足夠的來源答案；重排後仍保留說話者、限定、預測與事實的差異。
- 第一個原音答案直接回答標題／縮圖承諾；首題比較涵蓋本集所有問題。
- 片頭口播說清楚來源定位、相關背景、誰訪問誰或誰在講解，以及觀看價值。
- 串場只提供理解所需的資訊，來源人物的原音承載核心回答。

不確定的字幕和專名回到原音查核，保留原 ASR、修正文字與依據。無法確認時，不用看似流暢的翻譯掩蓋缺口；記錄時間碼、可能影響及待確認狀態。

來源說話者的自述可以按自述呈現；外加的職務、數字、新聞與主張另外查證。不要把一般背景材料偽裝成本集原片內容。

## 文字與旁白輸入

先執行 `check_narration.py --text-file voice/approved-narration.txt`。核對正式旁白、實際錄製／合成輸入、術語與片頭覆蓋；它不會查證每一句的事實。

生成後按 [聲音與專名](voice-and-terms.md) 實聽，再記當前 WAV hash 和核聽範圍，執行 `--require-listening`。沒有實聽時，`audio_reviews` 不得填入完成記錄。

若音檔變更，更新發音審查、字幕與卡片，重新 resolve。即使檔名相同，WAV bytes 改變也會使舊審查失效。

## 技術檢查

```powershell
& $py -X utf8 "$skill/scripts/opening_selection.py" $episode
& $py -X utf8 "$skill/scripts/interview.py" resolve $episode
& $py -X utf8 "$skill/scripts/interview.py" check $episode
& $py -X utf8 "$skill/scripts/build_film.py" $episode
```

確認切片長度吻合候選、字幕沒有跨越切點、旁白字幕落在 WAV 內、卡片覆蓋實測聲音、影格連續、總時長符合本次要求。`qa/resolved-plan.json` 是計算結果，避免直接手改。

渲染後以最終 MP4 檢查：

```powershell
& $py -X utf8 "$skill/scripts/interview.py" check $episode --video "$episode/exports/final.mp4" --decode
```

此命令檢查 1080p、30 fps、實測時長、影格數、音軌及完整解碼。解碼成功只證明檔案可解，不證明內容正確、沒有遮擋或聲音舒適。

## 實際影格與動態

從最新最終 MP4 抽取代表影格，包含 hook、人物卡、最長字幕、進度圖示、片尾及每個 marker 的完整動作。動作檢查至少涵蓋全幅前、縮入中、穩定態、每個重點揭示後、離場中、恢復後。

```powershell
& '<ffmpeg>' -v error -ss 12.5 -i "$episode/exports/final.mp4" -frames:v 1 "$episode/qa/frame-12-5.png"
```

時間碼由本集 resolved plan 推算後再選取，上例無指定語意。截圖命令產生檔案後必須真的查看，才算視覺檢查。

影格 manifest 相對路徑以 manifest 所在目錄為基準：

```json
{"frames":[{"path":"frames/source-caption.png","narration":false},{"path":"frames/narration-caption.png","narration":true}]}
```

```powershell
& $py -X utf8 "$skill/scripts/check_style.py" $episode --frames "$episode/qa/frame-manifest.json" --delivery
```

此檢查適用附帶的紙張與縮入模板，會核對場景元件、marker 和部分影格證據。縮圖 review 欄位仍是審查者聲明；工具不會替你判斷人物是否忠實或標題是否誘導。

實看人物嘴部、來源文字、台標與右上角進度是否互相遮住。照片膠帶、箭頭、卡片重疊、黃色標記和字幕撕紙邊須在同類元件一致。接觸表與單張截圖無法證明動畫流暢，仍需看動態序列。

任何後製、修字、變速或音量處理都可能讓舊影格證據過期。最後報告以實際交付版本為準，更新其 hash、抽格與核聽範圍。

## 連續視聽

用一般觀看速度聽看完整輸出：注意原問答是否完整、旁白是否過量、問題是否清楚、中文字幕能否讀完、原音與旁白音量是否穩定、句尾是否被切斷。

角色和新名詞出現時，給觀眾足夠時間辨識；重點出場與來源說話時機一致。聽完問題後不應立刻被下一場蓋過，片尾也要留可閱讀的停留時間。

保存實際檢查時間範圍、發現問題和修正版本。無法完成連續觀看／核聽時，狀態寫 `partial`，例如「完成全檔解碼與所有 marker 抽格，尚未連續觀看 04:20–06:10」；不能只寫籠統的「已驗證」。

## 交付清單與版本

| 交付物 | 最低內容 |
|---|---|
| `final.mp4` | 最新可播放成片，實際規格與時長已記錄 |
| 縮圖 | 實際輸出檔、手機尺寸可讀、承諾吻合首答 |
| `title.txt`、`description.md` | 最終標題、原片頻道／標題／連結、必要歸屬 |
| `chapters.txt`、SRT | 與最終時間軸對齊；沒有英文來源時不假造英文內容 |
| 可編輯工程與 JSON | 來源切點、旁白、字幕、素材位置和視覺設定 |
| QA 記錄 | 使用版本、結構檢查、視聽範圍、未完成項、最終檔 hash |

保留 revision 編號或日期目錄，清楚標記哪份是交付版；重生某一段時只更新受影響內容，再解析後續時間。舊檔可留供回復，但不能讓說明檔指向不同版本。

分享可編輯工程前確認其中素材、字型、聲音與外部依賴的分發權利；機器設定與金鑰不放進交付包。發布、上傳或改為公開依本次授權執行，製作完成本身不代表已授權發布。

## 編輯式完整修訂的補充證據

保留旧版，輸出新revision。沿用媒體時，先比對原稿／聲線／原音範圍及SHA：已處理WAV可逐byte核對，來源音軌可比對AAC packets；不知道處理狀態就保留unknown。不重新增益或變速來掩蓋未核對的同步。

最終MP4逐段頭尾對位、原生立體峰值、每張卡before／縮入中／穩定／各step／離場／還原、最長中英字幕及片尾全部內容都需有實際證據。DOM、數值相關、解碼和抽格只是各自範圍的檢查，不能宣稱已連續聽看。發布或更新共享Skill只帶流程／腳本／模板；不帶來源影片、逐字稿、個人路徑、私有聲包或金鑰。
