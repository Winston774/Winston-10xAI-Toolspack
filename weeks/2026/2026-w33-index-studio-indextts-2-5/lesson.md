# 教學講義：把模型宣稱變成可重現的聲音實驗

## 核心 Workflow

```text
合法聲紋 → 固定基準 → 單一變因 → 本機生成 → WAV + JSON → 人工聆聽 → 下一輪假設
```

這週的重點是實驗設計。只聽一個「看起來不錯」的音檔，無法知道效果來自聲紋、文字、Seed、情緒、語速或採樣參數。

## 系統模組

1. `webui.html`：無 CDN、無打包器的單檔 UI，負責表單、狀態、播放與下載。
2. `htmlui_server.py`：輸入驗證、暫存上傳、正體轉換、GPU Lock、WAV 與 JSON。
3. `indextts/`：IndexTTS 2.5 推論與音訊模型。
4. `outputs/htmlui/`：本機實驗產物，預設不進入 Git。
5. `tests/test_htmlui.py`：不載入 GPU 模型也能驗證 UI／API 合約。

## 動手做

### 1. 建立基準

- 聲紋：同一段 5–15 秒乾淨音檔。
- 文字：20–50 字、標點自然。
- Seed `42`、Temperature `0.8`、Top P `0.8`、Top K `30`、Num Beams `3`。
- 情緒：沿用聲音情緒。
- 時長係數：`1.0`。

生成後立刻確認 WAV 可播放，並打開對應 JSON。基準是後續所有比較的控制組。

### 2. 語速 A/B

複製同一組條件，只改：

- A：`duration_factor = 0.8`
- B：`duration_factor = 1.2`

比較實際時長、咬字、停頓與自然度。係數大於 1 代表音訊時長增加、語速變慢。

### 3. 情緒 A/B

選擇一種模式：

- 情緒參考音檔：聲紋與情緒來源分開。
- 八維向量：一次提高一個維度，例如悲傷 `0.8`。
- 文字描述：用一句情境描述驅動情緒。

固定其他參數，比較情緒辨識與聲紋是否漂移。

### 4. 保存實驗證據

用這張表記錄：

| Run | 唯一變因 | WAV 秒數 | 聲紋相似 1–5 | 可懂度 1–5 | 自然度 1–5 | 備註 |
|---|---|---:|---:|---:|---:|---|
| Base | 無 |  |  |  |  |  |
| Speed A | 0.8 |  |  |  |  |  |
| Speed B | 1.2 |  |  |  |  |  |
| Emotion |  |  |  |  |  |  |

## Agent Workflow

Codex 可協助：

- 檢查兩份 JSON 是否真的只差一個欄位。
- 將觀察整理成下一輪實驗矩陣。
- 診斷啟動、API、檔案或參數合約錯誤。

提供最小證據即可：錯誤文字、health JSON、兩份參數摘要與 GPU／Python／uv 版本。聲紋與 WAV 不需上傳給 Agent。

## 成本優化

- 基本語音推論是本機 GPU 計算，沒有 LLM Token 成本。
- 一輪只改一個變因，可用更少生成次數找到有效參數。
- 先用短句驗證 Workflow，再跑長文。
- 先檢查 health 與合約測試，避免模型每次都重新載入。

## 延伸挑戰

- 寫一個腳本比較 JSON，只允許白名單欄位變化。
- 加入 ASR WER 或說話者嵌入相似度，並保留人工評分。
- 設計一個實驗佇列，但維持單 GPU 串行與每筆權限證據。
- 為生成檔加入資料保存期限與一鍵清理功能。
