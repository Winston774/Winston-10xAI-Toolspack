# 支援範圍與限制

| 功能 | 本版範圍 |
|---|---|
| 瀏覽器 | manifest 最低 Chrome 120，桌面版載入未封裝項目；其他瀏覽器未驗收 |
| X 來源 | HTTPS 直接 MP4；公開 embed 或貼文頁可提供 MP4 的 blob／串流播放器 |
| Threads 來源 | HTTPS 直接 MP4；可從內嵌／同站貼文 JSON 找到 MP4 的 blob／串流播放器 |
| 多影片 | 封面、播放器長度與比例可唯一定位時支援；資料不足或匹配不唯一會停止 |
| 接收 | Threads 桌面新串文、www.facebook.com 一般新貼文視窗；依語意標籤和 DOM 結構辨認 |
| 其他入口 | 回覆、留言、多段串文、Reels、限時動態、Messenger、Business Suite 未支援或未驗收 |
| 檔案與快取 | 單支 MP4，最多 150 MiB；快取一支，未提供歷史影片清單 |
| 聲音與編碼 | 保留來源 MP4 bytes，不轉碼、不補音軌；需 Chrome 能讀取有效時長與尺寸 |
| 其他平台 | 使用已下載 MP4 手動選檔上傳 |

剪貼簿標記需要接收頁的外掛程式解讀，在一般網站或桌面應用程式可能顯示識別文字。外掛沒有提供通用的系統影片檔案剪貼簿。

X 公開 embed 與貼文頁解析、Threads 內嵌資料皆依賴網站當時格式。私人、刪除、受限、需額外驗證、限流或已到期媒體可能失敗；不提供繞過存取限制的功能。X 文章／影片檢視器的頁面備援需要可匹配的封面媒體 ID。

媒體下載要求 HTTP 200、大小上限與 MP4 檔頭，再由 Chrome 讀中繼資料；這些檢查無法代替完整播放驗收。貼文頁的 8 MiB 字元檢查在讀取完成後執行，不能視為串流記憶體硬限制；接收重建 File 也會產生額外記憶體用量。

接收端以中英文標籤辨識新貼文，平台語言、改版或帳號差異可能不相容。寫入 input.files 與送出事件之後，仍需確認平台真正接受附件與完成上傳。

本週維持 **Preview**。自動測試通過範圍見 [verification](verification.md)；已登入 Chrome 安裝後的右鍵、剪貼簿、Threads／Facebook 附件預覽與上傳完成，尚未在本次重新驗收。
