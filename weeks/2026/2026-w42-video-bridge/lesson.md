# 本週講義｜建立可確認結果的影片接力流程

## 任務

用一支有權使用的 X／Threads 影片完成下載，辨認快取、剪貼簿及下載狀態；再選擇一個支援的發文視窗練習附件插入。基本操作以 Chrome 介面完成。開發者可延伸閱讀訊息流程與執行測試。

## 1. 安裝與來源選取（約 30 分鐘）

依 [README](README.md) 安裝 `completed/video-bridge/extension`，重新整理平台分頁，確認版本 `0.3.0`。選擇一支小於 150 MiB、可公開取得且有使用權的影片，直接在影片畫面上按右鍵。

使用「下載並複製影片・影片接力」後，查看工具列面板：檔名、大小、時長、尺寸、來源貼文與錯誤。到 Chrome 下載項目確認完成並開檔播放。觀察「已交給 Chrome 下載」到「下載完成」的差異；若原片有聲音，也核對下載檔有聲音。

**練習重點：** 多影片或引用貼文容易造成來源混淆。核對影片畫面與來源，遇到無法唯一確認的訊息時，開啟原始貼文、播放並重新右鍵。

## 2. 快取與剪貼簿（約 15 分鐘）

複製一般文字覆蓋剪貼簿，再從面板點「準備再次貼上」。理解標記對應目前快取；新影片成功取得後替換舊快取，舊標記即失效。

也可以只用右鍵「複製影片・影片接力」，觀察面板已備妥，但沒有額外下載請求。面板「另存影片」可再交給 Chrome 選擇儲存位置。

## 3. 接收與重試（約 15 分鐘）

插入會把檔案交給社群平台，可能立即上傳。使用自己的帳號和可上傳素材，開啟 Threads 新串文或 Facebook 一般發文視窗，只留一個可見發文視窗。

在文字區按 Ctrl＋V，或使用浮動插入按鈕。核對附件預覽、原本附件、上傳處理狀態；本週練習可在確認後取消發文。同一視窗再次插入相同影片會被阻擋，移除後要再插入可關閉並重開視窗。

若平台只出現識別文字，先確認來源與接收分頁已重新整理、外掛已啟用及入口受支援；參考 [疑難排解](docs/troubleshooting.md)。平台欄位不相容時，可改用已下載 MP4 透過平台「相片／影片」手動選檔。

## 4. 觀察狀態與程式（約 30 分鐘）

閱讀 [架構](docs/architecture.md) 及 [權限](docs/permissions-and-privacy.md)，回答：

1. 影片 bytes 與剪貼簿標記各存在哪裡？清除快取會影響哪些資料？
2. X 的公開 MP4 解析與 Threads 貼文頁備援在哪個環境執行？登入狀態有何差異？
3. 接收端在等待資料時，為何要反覆確認同一個發文視窗、文字區及附件欄位？
4. Chrome 下載受理、附件欄位寫入、平台上傳完成分別需要什麼證據？

開發延伸：在 `completed/video-bridge` 執行 `npm.cmd run validate`。無需 npm install；測試使用 Node.js 內建功能與模擬資料，操作細節見 [成品 README](completed/video-bridge/README.md)。

## 成果證據與通過標準

| 證據 | 通過標準 |
|---|---|
| Chrome 擴充功能畫面 | 載入正確資料夾、顯示 v0.3.0，沒有載入錯誤 |
| 面板與來源摘要 | 檔案資訊可見，所選影片與來源對應；分享截圖時遮蔽私人貼文與帳號 |
| Chrome 下載與實際播放 | 下載完成，畫面正確；有音軌來源核對聲音，記錄實測結果 |
| 平台附件預覽（接收路徑） | 正確影片出現在唯一新貼文視窗；原附件保留，上傳處理狀態有確認 |
| 重試與說明 | 能說明標記、快取、下載的差異，記下未通過項目及重試結果 |

無法完成平台接收時，保留「下載路徑通過／接收待驗」紀錄。先依症狀重試，再以手動選檔完成自己的工作；不要把提示文字當成平台已接受的證據。
