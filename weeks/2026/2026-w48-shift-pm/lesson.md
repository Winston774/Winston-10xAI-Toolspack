# 45 分鐘實作｜從「能跑」寫出下一張工單

學習成果：能判斷 Chrome 外掛的目前階段，說明暫不增加的服務，並寫出可實際驗收的下一張工單。

1. **10 分鐘｜選情境。** 有專案就選一條已能運作的旅程；沒有專案用 [段落筆記案例](starter/paragraph-notes.md)。回報只根據提供的證據，標示程式未執行的部分。
2. **15 分鐘｜產出一頁決策。** 用 README 的提示詞叫 `$shift-pm`，要求列出現在必做、先省略、最大阻塞與下一張工單；如果技能增加了你還用不到的登入、雲端或付費流程，請它說明觸發條件。
3. **15 分鐘｜定出可重跑的驗收。** 用 [工單範本](completed/shift-pm/assets/work-order.md)，把正常和失敗情境各寫一個，標記 G1–G4 當前狀態與缺的證據。尚無實作也可以先寫工單，閘門先保持 `pending`。
4. **5 分鐘｜決定下次切片。** 檢查有沒有把「開了 PR」、「測試有過」、「可以公開」混成一件事。最後只排一個下一步。

## 通過標準

- 說得出：目前階段、試用者、核心動作與看得到的成果。
- 有一項明確延後的功能、延後原因及重啟條件；沒有先裝不需要的服務。
- 工單標明範圍、正常／失敗案例、可觀察的通過標準與阻塞。所有沒跑的測試都標成未驗證。
- 輸出沒有帳號、金鑰、真實用戶資料，也沒有擅自公開或送審。

**卡住時**：找不到技能就核對 README 的安裝路徑；沒有專案就從示範案例起跑；結果太總體就把目標改成「先找五位同學測一條旅程，只給一張工單」。
