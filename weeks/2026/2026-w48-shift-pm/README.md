# Shift PM｜從 MVP 到 Production 的產品化助手

Chrome 外掛已經能跑，接下來該找人試用、做登入、準備上架，還是先補測試？把手上的專案交給 `$shift-pm`，它會依目前的使用者旅程、資料、成本與發行目標，整理**現在先做什麼、哪些可以晚點做，以及怎麼驗收**。

適合做 Chrome 外掛的獨立開發者與小團隊。這是 **Codex 技能**，安裝在開發工作區；不需安裝另一個 Chrome 外掛，也不需新增 API 金鑰、npm 或雲端帳號。原專案的測試仍依其本身環境執行。

## 安裝到你的專案

1. 下載本週教材 ZIP 並完整解壓。若用 GitHub 分支的「Code → Download ZIP」，先進入 `weeks/2026/2026-w48-shift-pm/`。
2. 將 [completed 裡的整個 `shift-pm` 資料夾](completed/shift-pm/SKILL.md) 複製到**你的 Chrome 外掛專案根目錄**的 `.agents/skills/`；沒有資料夾就建立。保留 `references/`、`assets/` 和 `agents/`。
3. 結果應是 `你的專案/.agents/skills/shift-pm/SKILL.md`。在 Codex 開啟那個外掛專案，新建對話後輸入 `$shift-pm`，確認可以選用。找不到時核對工作目錄與資料夾層級，必要時重新啟動 Codex。

已裝同名技能時，先比較版本；不要直接覆蓋。支援的發現位置和呼叫方式可查 [Codex Skills 官方指南](https://developers.openai.com/codex/skills)。只想先試、不安裝，可把完整 `shift-pm` 資料夾交給 Codex，要求先讀其中的 `SKILL.md` 及相關參考，再跑 [45 分鐘練習](lesson.md)。

## 什麼時候叫它幫忙？

| 你在哪一站 | 可以這樣問 | 會拿到什麼 |
|---|---|---|
| 有想法／剛做出 MVP | 「先唯讀盤點，純本機版要補什麼？我現在需要登入嗎？」 | 現況與目標、最小架構、先做與延後清單 |
| 準備找人封測 | 「只支援一種頁面，幫我拆第一張工單，寫正常與失敗的測試。」 | 範圍、依賴、通過標準、實作與審查分工 |
| 準備上架 | 「檢查權限、隱私、送審素材和回復方案，先不要送件。」 | `已驗證／待驗證／阻塞` 清單與 Owner 待辦 |
| 開始有登入、同步或 API 成本 | 「用我的使用量假設試算，決定配額或收費哪些該先做。」 | 取捨、正常／壓力情境、成本上限與驗證方式 |

第一次可直接貼這句：

> 用 $shift-pm 唯讀看我的 Chrome 外掛。它現在能完成＿＿，我想先讓＿＿試用。請告訴我目前階段、現在最該修或驗證哪件事、哪些先不做，再寫一張含通過標準的工單。先不要改檔、部署或上架。

下一輪拿實際測試紀錄或 diff 回來，請它照工單驗收，再決定是否往下一階段。技能會建議需要的工作，正式部署、送審、開通付費服務和發布仍由你核准。版本 `0.1.0 Preview`；[練習](lesson.md)｜[驗證範圍](docs/verification.md)。
