# 成本、收費與第一個成長實驗

只有需求需要收費或外部 API 時才導入這一頁。先圈定單位（每次操作、每席、每月），在同一單位下對齊收入與成本。

1. **列假設**：售價、使用量、每次上游費用、金流、退款／失敗重試、儲存和直接支援成本。固定費與每單位變動費分開；若已把金流費扣進淨收入，別再次列為成本。標記幣別、估算區間與查價日期。
2. **試算一般與壓力情境**：單位貢獻＝收入扣除同單位的變動成本。用假設數字練習：每月每人收入 100 單位、金流與支援 10、每次呼叫 2，平常 20 次時單位貢獻 50；如果增加至 50 次，則為 -10（均未扣固定費）。選擇可接受的用量上限、成本告警與停止條件；不把假設當成利潤承諾。
3. **選收費策略**：本機功能可先免費驗證用途；有持續同步或工作流價值才比較定期方案；成本跟用量走時先解決成本保護，再評估配額或其他方案。避免同時建立多個方案；資格、支付、稅務和地區限制需另向官方及專業人員核對。
4. **量一個活化事件**：先定義「第一次有用」的可觀察結果，例如第一次在一個支援頁面完成匯出。只用必要、可披露的事件；不要記錄網頁內容、輸入文本、金鑰或敏感識別資料。每次只改一項引導、失敗訊息或入口，寫出比較方式、觀察區間與停止條件。使用真實遙測前另行評估必要性及取得授權。
