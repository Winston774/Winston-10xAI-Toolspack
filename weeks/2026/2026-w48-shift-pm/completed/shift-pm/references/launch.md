# 上架與正式營運檢核

這是準備清單。每次依 [Chrome Web Store 官方政策](https://developer.chrome.com/docs/webstore/program-policies/) 與當前控制台核對規則、實際選項及審核需求。紀錄「已備妥」與「已通過平台審查」的差異，不保證過審或固定時程。

## 本機測試 → 小規模試用 → 核准後公開

1. **本機**：用 [Load unpacked 官方步驟](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked) 在測試用 Chrome 設定檔載入指定目錄。核對 manifest 與權限、核心成功案例、權限拒絕、重新載入與更新後的行為。涉及 service worker 時，測背景重啟後狀態恢復；沒有適合的瀏覽器則標未驗證。
2. **試用**：用單獨環境、測試帳號和合成資料跑核心旅程。與正式環境比對 API 位置、外掛版本、資料隔離及設定。若有付款，使用供應商核准的沙盒；檢查同一事件重複、到達順序不同、取消／退款狀態的正確性，不測真實扣款。
3. **送審素材**：列清楚主要用途、每一項權限的使用理由、擷取與外送的資料、隱私揭露、支援方式、測試路徑、清理過的套件、截圖及審查說明。只寫能用當前版本證明的功能。隱私或付款聲明由 Owner 與適當專業人士核對。
4. **公開前**：核對欲發布版本、帳號、環境、預算與回復方案；準備舊版／修正版、可暫停的功能、通知窗口、相容的資料復原。先寫 go/no-go 條件；公開、更新權限、正式金流、外部提交都依授權執行。
5. **公開後**：看首個成果完成率、失敗率與實際成本；紀錄異常時誰收到告警、何時停止擴量及如何復驗。

## 防禦性驗收清單

- 最小權限與資料最小化；密鑰、測試端點、私人樣本不進發行套件。
- 登入與資料隔離依專案自己的資料流驗證；權限決策由受信任的服務執行，避開只相信客戶端宣告。
- 扣額、收費及狀態更新要能安全地重試；容錯測試使用本機／沙盒的合成事件。必要時請專人做正式安全或合規審查。
- 升版及縮回時資料依然可用；新舊版本互通、舊資料遷移與故障訊息可回復。若未演練回復，標成待做，不承諾可即時復原。
