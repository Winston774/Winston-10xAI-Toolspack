# Phase 0：啟動診斷與通用四維決策矩陣

> **給 Agent 的強制指令**：每位創辦人做的 Chrome 外掛完全不同——可能是生產力工具、AI 寫作／摘要、電商選品分析、社群增長助手、CRM 側邊欄、研究筆記、或是多媒體工具。**在規劃任何技術棧、資料庫或收費設計前，務必先完成本文件的診斷，依對方真實情境給出量身建議，絕不硬套單一產品模板！**

## Step 1：先唯讀掃描現有專案（若已有程式碼）

在發問前先快速檢查工作區，避免問出程式碼裡已有的資訊：
1. **外掛基礎盤點（`manifest.json` 與源碼）**：
   - Manifest 版本（必須為 MV3）與所申請的權限（`permissions`、`host_permissions`、`offscreen`、`externally_connectable`）。
   - 核心運算發生在哪裡？純瀏覽器本地運算、呼叫自有後端、還是前端直連付費第三方 API（BYOK）？
   - 是否有送審地雷：硬編碼 API Key、本機檔案路徑（`C:/`、`D:/`）、測試用違規網域、違反 Chrome Web Store / 金流政策的宣稱或邏輯。
2. **開發環境與工具鏈**：
   - 作業系統（Windows PowerShell 呼叫 npm 須用 `npm.cmd`；macOS/Linux 用 `npm`）。
   - 已安裝 CLI：`git`、`gh`、`node`、`wrangler`，以及是否同時具備多個 AI Agent（如 Claude Code + Codex）可做異質交叉審查。
3. **既有商業元件**：是否已有網域、官網、資料庫、金流或 CWS 開發者草稿？

## Step 2：精準訪談創辦人（5 個決定架構與商業方向的問題）

一次問完以下 5 題（若從程式碼已可推測，列出推測請創辦人確認即可）：

1. **目前階段與核心功能**：目前處於點子／本機原型／BYOK 工具／已上架免費外掛？外掛替使用者完成什麼核心任務？
2. **運算與成本結構**：
   - 功能在瀏覽器本地就跑得完（變動成本 ≈ \$0），還是每次使用都會消耗你的付費 API（LLM／OCR／搜尋／資料強化／影音／爬蟲）？
   - 是否需要跨裝置雲端同步使用者資料？不同使用者會不會重複查詢相同的公開資源（可透過快取降低成本）？
3. **目標客群與收費直覺**：目標是個人消費者（B2C）、專業工作者（Prosumer）還是團隊／企業（B2B）？傾向一次買斷、固定月／年費、還是依用量／點數計費？
4. **營運地區、主體與語系**：創辦人所在國家／地區（直接影響金流與稅務選擇）？預計以個人還是公司名義收款？首發要支援哪些語言（建議英文全球預設 ＋ 創辦人母語）？
5. **預算與推進節奏**：希望先用 \$0 免費層驗證市場（Staging / MVP），還是直接按正式上線規格（約 \$30/月起）建置？

## Step 3：四維決策矩陣（幫助創辦人明確做決定）

### 維度 1：依「資源與成本拓撲」選擇技術架構（Pattern 1–4）

用**技術與成本特性**（而非特定產品題材）將外掛歸類，只建置真正需要的層：

| 架構模式 | 適用情境（舉例） | 必建元件 | **明確建議先省略（避免過度設計）** |
| :--- | :--- | :--- | :--- |
| **Pattern 1：純本地功能解鎖型**<br>*(Zero Variable Cost)* | 頁面樣式／截圖／匯出工具、本機計算器、快捷鍵強化、離線開發者小工具 | 輕量授權驗證 API ＋ 金流 Webhook ＋ 靜態官網／法務頁 ＋ 簡易會員頁 | ❌ 複雜點數扣款帳本<br>❌ 大容量物件快取（R2）<br>❌ AI 成本熔斷器與多供應商備援 |
| **Pattern 2：雲端資料同步／協作型**<br>*(Stateful CRUD SaaS)* | 筆記剪藏、書籤管理、CRM 側邊欄、多裝置設定／範本／歷史紀錄同步 | Auth ＋ PostgreSQL（RLS 權限隔離）＋ 輕量 API ＋ 金流 Webhook ＋ 會員控制台 | ❌ 複雜計量扣點帳本<br>❌ 每日 API 成本熔斷器<br>❌ 跨用戶共享快取 |
| **Pattern 3：API／AI 計量型**<br>*(Usage-Metered SaaS)* | 任何會呼叫付費第三方 API（LLM、OCR、資料爬蟲、商業資料查詢、圖像／語音處理）的外掛，用越多你的帳單越高 | **全套核心棧**：Zero-BYOK API Proxy ＋ PostgreSQL 原子點數／配額帳本 ＋ Redis（限流＋即時停權＋**每日成本熔斷**）＋ Turnstile 防刷 ＋ 金流 ＋ 雙供應商備援 ＋ 官網與控制台 | ⚠️ 若每次結果都高度個人化、用戶間無重疊，**省略跨用戶共享快取** |
| **Pattern 4：高流量／可共享快取或大物件型**<br>*(Cache-Leveraged High-Margin SaaS)* | 在 Pattern 2 或 3 基礎上，多位用戶會反覆查詢**同一份公開資源**（如熱門公開網頁、商品頁、公開文件／資料庫、熱門公開影音），或需儲存大型產物與限制併發連線 | 全部 Pattern 3 ＋ **私有物件儲存／共享快取（Cloudflare R2，\$0 出站費）** ＋ 後端簽章防快取下毒 ＋ Redis 併發連線鎖 ＋ 用戶共享開關與內容下架機制（DMCA／Takedown） | （僅在確認「跨用戶命中率有機會 ≥ 15%」或「需低成本存大檔」時啟用！） |

### 維度 2：收費模式與 BYOK 策略決策樹

| 你的產品條件 | 推薦收費模式 | BYOK 建議 | 決策理由 |
| :--- | :--- | :--- | :--- |
| **Pattern 1**（變動成本 ≈ \$0），偏工具型一次需求 | **一次性買斷（\$19–\$49）** 或 **低價年訂閱（\$19–\$39/年）** | 不適用（無上游 Key） | 一次買斷轉化快、客服低；若持續維護網站相容性（DOM 常改版），年費能支撐長期維護。 |
| **Pattern 1 / 2**（固定低成本），高頻日常工作流 | **固定月／年訂閱（Freemium 功能分級）** | 不適用 | 免費版給基礎功能建立習慣，付費版解鎖匯出、無限筆數、雲端同步或團隊功能，毛利常達 85–95%。 |
| **Pattern 3 / 4**（每次使用都有上游 API 成本） | **月／年訂閱配額 ＋ 永不過期加購包（Hybrid Credits）**，預設年繳 | **強烈建議 Zero-BYOK（100% 雲端代管）** | 1. 保護核心 Prompt、規則與模型路由不被反編譯抄襲；<br>2. 大眾用戶不想自己去申請 API Key；<br>3. 配額制防止重度用戶把你用到虧錢，永不過期加購包消除輕度用戶「怕浪費」的抗拒。 |
| **Pattern 3**，但受眾純屬**工程師／極客**且你想零維護變現 | **一次性買斷 UI 授權** | 可考慮保留 BYOK | 免扛上游 API 帳單與濫刷風險，但天花板與續費估值遠低於雲端代管 SaaS。 |

### 維度 3：依「創辦人所在地與主體」決定金流方案

| 創辦人所在地／條件 | 首選金流 | 核心理由 | 備選 |
| :--- | :--- | :--- | :--- |
| **台灣、香港、東南亞、拉美或任何無當地 Stripe 帳戶的創辦人**（個人或公司皆可） | **Paddle Billing v2（Merchant of Record, MoR）** | 1. 名義賣家代收代報全球 VAT／銷售稅，單人創辦人完全免稅務噩夢；<br>2. 個人通過 KYC 即可直接收全球卡／PayPal 並匯回本地銀行；<br>3. 費率透明單一（`5% + \$0.50`），無額外跨境卡加收。 | Lemon Squeezy、Polar（偏開發者產品） |
| **已在美國／新加坡／日本／歐盟設立公司，且有財稅人員處理跨國稅務** | **Stripe Billing + Stripe Tax**（或仍選 **Paddle** 省心） | Stripe 基礎費率較低，但須自負全球稅務申報與爭議處理（Chargeback）；1–3 人小團隊往往選 MoR 總成本更低。 | Paddle Billing v2 |

## Phase 0 交付物：《一頁式架構與商業決策簡報》

完成上述訪談後，先產出這份 1 頁簡報請創辦人確認，再進入 M0：
1. **架構判定**：Pattern 1 / 2 / 3 / 4 ＋ BYOK 結論。
2. **裁剪後服務清單**：明確列出「現在必裝」、「上線才升級」、「本專案不需要」與月費估算。
3. **收費與毛利試算**：定價結構、單次／單月最壞變動成本、扣除金流手續費後的最壞毛利率（目標 ≥ 55%，平均 ≥ 75%）。
4. **GTM 切入假設**：目標核心付費受眾（Beachhead）＋ 首波免費獲客管道（SEO／CWS ASO／社群示範）。
5. **Day 1 創辦人啟動清單（Batch A）**：GitHub 私有倉、法定營運主體與網域信箱、Chrome Web Store \$5 永久 32 碼 Extension ID 草稿。
