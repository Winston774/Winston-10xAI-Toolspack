# 2026-W32：Goal Me — AI Agent 目標任務書

> 把一句模糊想法整理成 AI Agent 可以獨立執行、續跑與驗收的完整工作規格。

## 本週成果

本週提供 `goal-me v1.0.0`。它會先檢查工作區與可用環境，只針對無法自行查證、而且會改變方案的事項提問，再產出可直接貼給執行 Agent 的目標任務書。

主要能力：

- 將一句話需求分成執行型、探索型或混合型任務。
- 區分已實測、使用者決定與暫定假設，降低 Agent 編造基準或指令的風險。
- 定義允許寫入、唯讀與禁止操作的範圍。
- 加入防取巧驗收、反向驗證、三道止損與斷點續跑。
- 經使用者同意後，拆成寫入範圍不重疊的多 Agent 任務書。
- 支援有 `/goal` 目標模式與只有一般對話輸入的 Agent 工具。

成品位置：[`completed/goal-me/`](completed/goal-me/)

延伸文件：

## 基本資料

- 類型：AI Skill
- 難度：中級
- 預估時間：安裝與第一次使用約 20 分鐘；完整練習約 60 分鐘
- 支援平台：Codex、Claude Code，以及可讀取 Agent Skills 或接受完整提示詞的 AI Agent
- Skill 版本：`1.0.0`
- 本週狀態：`Stable`

## 需要準備

- 一個可使用技能或讀取 `SKILL.md` 的 AI Agent。
- 一句想交給 Agent 完成的真實需求。
- 若需求涉及程式碼，準備一個可安全練習的本機專案。
- 若要產出實測基準，Agent 需要該工作區的讀取與執行權限。
- 若要查詢近期資訊，Agent 需要可用的連網研究工具。

安裝技能本身不需要 API Key，也不會自動部署、推送、寄信、刪除資料或產生付費操作。實際執行任務是否使用付費模型或外部服務，依學員自己的工具與帳號方案而定。

## 安裝與開始

### 不使用 Git

1. 從 [`2026-w32-v1.0.0` GitHub Release](https://github.com/Winston774/Winston-10xAI-Toolspack/releases/tag/2026-w32-v1.0.0) 下載 `2026-w32-goal-me-agent-task-brief.zip` 並解壓縮。
2. 找到 `completed/goal-me`。
3. 將整個 `goal-me` 資料夾複製到個人技能目錄：
   - Codex：`%USERPROFILE%\.codex\skills\goal-me`
   - Claude Code：`%USERPROFILE%\.claude\skills\goal-me`
   - macOS／Linux 將 `%USERPROFILE%` 改成 `~`。
4. 若工具沒有立即發現新技能，重新啟動該工具。

Claude Code 的技能目錄與呼叫方式可參考[官方 Skills 文件](https://code.claude.com/docs/en/skills)。若使用其他 Agent 工具，請依該工具的技能安裝目錄調整；無法安裝技能時，也可以直接將 [`SKILL.md`](completed/goal-me/SKILL.md) 與任務需求交給 Agent。

### 呼叫技能

在 Codex 輸入：

```text
使用 $goal-me，幫我把「讓 Agent 把這個專案的測試流程整理好」轉成可獨立執行的目標任務書。
```

在 Claude Code 輸入：

```text
/goal-me 幫我把「讓 Agent 把這個專案的測試流程整理好」轉成可獨立執行的目標任務書。
```

技能若提出問題，請一次回答完；完成後會提供可複製的任務書。支援 `/goal` 的工具可依輸出說明貼入目標模式；沒有 `/goal` 時，直接貼到新的 Agent 對話即可。

## 使用示範

原始想法：

```text
幫我讓 Agent 把這個專案的測試流程整理好。
```

合格的流程應該是：

1. Agent 先讀取 `AGENTS.md`、套件腳本、現有測試與 CI，而不是先問 README 在哪裡。
2. 只詢問無法從工作區得知、而且會改變範圍或驗收的決策；單輪最多 5 題。
3. 將實測結果、使用者決定與暫定假設分開。
4. 任務書列出允許寫入、唯讀、禁止操作與停止條件。
5. 驗收同時涵蓋指令、產物、不退步與防取巧要求。

## 本週任務

1. 選一個可回復、沒有正式環境風險的真實需求。
2. 用一句話描述需求，不先替 Agent 拆步驟。
3. 使用 `goal-me` 產生一份目標任務書。
4. 檢查「這項工作為什麼要做」、「我先代你採用的預設決策」與「完成條件」。
5. 將任務書交給另一個 Agent 或新的會話執行；若不想真的修改檔案，可要求只完成任務 0 與執行計畫。
6. 執行完成後，帶回結果讓原本的規劃 Agent 驗收。

完整練習與探索型範例見[教學講義](lesson.md)。

## 成果證據

- 一張技能已被辨識或成功呼叫的截圖。
- 原始的一句話需求，以及技能提出的單輪問題；沒有問題時，保留「無需提問」的結果。
- 一份完整任務書，至少看見六節結構、權限邊界與完成條件。
- 一份執行或只讀預檢結果，包含實際證據、阻塞或遺留風險。
- 分享前遮蔽本機帳號、絕對路徑、API Key、客戶名稱與未公開內容。

## 通過標準

- [ ] `goal-me` 可以被 Agent 辨識，且會讀取 `references/anatomy.md`。
- [ ] 最終任務書可一次貼給單一執行 Agent；多 Agent 任務則每個 Agent 各一份。
- [ ] 關鍵資訊有區分 `已實測`、`使用者決定` 或 `暫定假設`。
- [ ] 任務書列出允許寫入、唯讀與禁止操作的範圍。
- [ ] 未驗證的指令或基準被放進任務 0，沒有偽裝成實測結果。
- [ ] 驗收同時涵蓋成果、不退步與至少一項防取巧要求。
- [ ] 長任務具有適量的止損、`PROGRESS.md` 或 `BLOCKED.md` 機制；小任務不會被多餘文件拖慢。
- [ ] 未經明確授權，不會要求部署、推送、寄送、刪除、付費或修改正式環境。

## 失敗時怎麼做

1. 技能沒有觸發：改用 `$goal-me` 或 `/goal-me` 明確呼叫。
2. 找不到六節規格：確認 `references/anatomy.md` 與 `SKILL.md` 保持相同相對位置。
3. 中文顯示亂碼：重新以 UTF-8 解壓縮或複製檔案。
4. 任務書過長：縮小為一個可獨立完成與驗收的目標，再重新產生。
5. Agent 編造指令：要求把無法實測的內容移到任務 0，並附驗證與停止條件。
6. 工具沒有 `/goal`：直接將整份任務書貼到新的 Agent 對話，不需要發明其他啟動指令。
7. 仍不符合預期：依[驗證文件](docs/verification.md)跑三個最小測試案例並保存輸出。

## 延伸挑戰

在使用者明確同意的前提下，將同一目標拆成兩個並行 Agent。檢查兩份任務書是否具有相同全域規格、不重疊寫入範圍、唯一共享檔案擁有者與清楚的整合順序。
