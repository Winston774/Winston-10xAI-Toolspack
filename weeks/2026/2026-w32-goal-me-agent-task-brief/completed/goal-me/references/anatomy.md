# 任務書六節規格

每份任務書固定使用以下六節。依任務複雜度調整篇幅，但不要刪除會影響獨立執行的資訊。

## 1. 這項工作為什麼要做

用兩行內說明：

- 要解決的問題或要做出的決策。
- 可觀察的成果，以及成果對使用者的價值。

不要把使用者指定的手段誤寫成最終目標。例如「加入 Redis」可能只是「降低延遲」的假設作法。若尚未驗證，將手段放入第 3 節的預設決策或第 4 節的驗證任務。

## 2. 已知現況與證據

只保留會影響執行的事實：

- `已實測`：指令、路徑、基準數字、版本或實際狀態。
- `使用者決定`：明確的產品、風險、時間或品質要求。
- `暫定假設`：驗證方法、成立門檻與不成立時的處理。

優先引用檔案路徑、測試名稱、schema、設計稿或來源連結。不得將 README、提案或舊報告當成目前實測。

## 3. 範圍、授權與預設決策

必須列出：

- **要完成**：本次交付內容。
- **不在範圍**：容易被誤做但本次不做的內容。
- **允許寫入**：精確路徑、分支、服務或資料範圍。
- **唯讀區域**：可取證但不可修改的範圍。
- **禁止操作**：未授權的部署、推送、傳送、刪除、付費、權限或正式環境操作。
- **我先代你採用的預設決策**：每項寫明預設值、原因、可接受風險及改判條件；沒有就寫「無」。

硬性限制必須可追溯到使用者決定、實測風險、安全要求或工具權限。其他內容寫成建議，不要假裝是不可違反的規則。

## 4. 執行任務與順序

### 執行型

依相依關係排列，不要按想到的先後排列：

1. **任務 0：前提與基準**：只放本次無法預先查證的項目；寫明不符時停止的位置。
2. **實作任務**：每項包含輸入、動作、輸出與局部驗證。
3. **整合任務**：說明接縫、相容性與整體驗證。
4. **收尾任務**：文件、清理、證據與狀態回報。

若測試與實作真實行為衝突，先判斷規格來源。需要保留現況但已知有缺陷時，可加入特性測試（characterization test，用測試固定目前行為）並明確標記 `KNOWN DEFECT`；不得藉此宣稱缺陷已修復。

### 探索型

不要硬塞程式碼指令或數量 KPI。改為：

1. 定義決策問題、排除範圍與時間截止點。
2. 先定比較準則與權重，再蒐集候選方案。
3. 要求一手資料優先，區分事實、推論與未知。
4. 主動找反證、失敗案例、轉換成本與維護成本。
5. 產出方案矩陣、建議、信心程度及仍需驗證的事項。

### 混合型

先完成探索階段，再用明確門檻決定是否實作。例如：只有候選方案通過安全、成本與相容性門檻才進入實作；否則停止並交付研究報告。不要讓執行 Agent 在門檻未達時為了「完成」而強行修改。

### 多 Agent

在每份任務書的本節最前面加入相同的「全域協作規格」：

- 整體成果與共同完成條件。
- Agent 名稱、唯一寫入範圍與輸出。
- 相依關係、共享介面、唯一共享檔案擁有者。
- 整合負責者、合併順序及整合後驗收。
- 跨範圍發現問題時，只記錄證據與影響，不擅自修改。

## 5. 執行控制與回復

依風險加入：

- **開工摘要**：長任務在動工前以 10 行內記錄目標、順序、基準、最大風險與下一個檢查點。
- **`PROGRESS.md`**：先指定允許寫入的追蹤位置，再記錄時間、已完成事項、證據、下一步、未解風險與最後一次驗收結果。
- **`BLOCKED.md`**：放在同一追蹤位置，記錄阻塞原因、原始錯誤、已試方法、受影響範圍、解除條件與安全的下一步。
- **止損**：前提不符、同一驗收連敗 3 次、結果退步或超出時間／成本上限時的處理。
- **回復**：只還原本次可辨識的變更，保留使用者與其他 Agent 的工作。

小型、單次即可完成的任務可以不建立進度檔，但停止條件與錯誤回報仍要清楚。

## 6. 完成條件與回報格式

### 執行型完成條件

同時涵蓋：

- 功能是否完成。
- 測試、型別、lint、建置或專案既有檢查是否通過。
- 基準是否未退步，略過與失敗是否未增加。
- 禁止取巧項目是否未發生。
- 產物、介面或外部狀態是否經合適方式驗證。
- 需要的反向驗證是否證明失敗會被偵測。

每一條都寫成可判定的證據：指令與預期結果、檔案與必要內容、畫面與人工步驟、API 回應、來源連結或狀態紀錄。不要寫「看起來正常」、「品質良好」等無法判定的句子。

### 探索型完成條件

要求：

- 回答原始決策問題，而非只堆資料。
- 比較準則一致，沒有為偏好方案臨時改標準。
- 關鍵主張有來源，並標示來源日期與可信度。
- 清楚區分事實、推論、假設與未知。
- 至少呈現主要反方證據、風險與未採用方案。
- 建議附適用條件、信心程度與下一個低成本驗證。

### 最終回報

要求執行 Agent 在結束時提供：

1. 結果：完成、部分完成或阻塞。
2. 變更或交付物清單。
3. 驗收證據與關鍵數字。
4. 未解風險、已知缺陷與未執行操作。
5. 續跑起點或建議下一步。
