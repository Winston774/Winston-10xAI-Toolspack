# W39 講義：讓 AI 在有限選項中做決策

## 本週目標

用一局俄羅斯方塊看懂四件事：怎麼描述狀態、怎麼列出可執行選項、怎麼拆分判斷、怎麼驗證與執行結果。約 120 分鐘，不需要有效 API Key 也能完成核心練習。

## 1. 先觀察一個回合（20 分鐘）

選「整理殘局」，使用本機預演的單步決策。先猜哪個落點比較好，再檢查畫面的提案。

記下兩個候選的欄位、旋轉、空洞數、高度與消行數。某個落點即使能消行，後續也可能留下空洞；不同動機會給這些因素不同權重。

預演由程式的固定評分與規則產生。它只試算當前方塊落下後的結果，沒有多步搜尋。相同起始棋盤與序列可重現，適合練習比較。

## 2. 看懂三層判斷（25 分鐘）

### 感知層：現在該重視什麼？

生存、整地、堆疊、消行、旋轉機會各有一個是／否問題。即時模式使用 Noul，回傳 yes 的機率。本範本以 0.5 為啟動門檻，這是應用程式設定。

### 提案層：各自想把方塊放哪裡？

活躍動機透過 Choice 在合法落點中選擇。程式另外提供本機基準。沒有活躍動機時仍執行第二批基準檢查，維持完整三批流程。

### 判定層：誰被選中？誰有風險？

裁判在提案之間給出 Choice 分布；同一批請求中的教練問題，分別評估各提案是否有明顯風險。本範本以 0.65 為否決門檻。

程式從未被否決的提案中按裁判機率選擇。全部被否決時明示本機基準備援。教練屬風險判斷，碰撞與落點合法性仍由引擎檢查。

Noul、Choice 的型別定義見 [Noul 官方文件](https://docs.typesafe.ai/primitives/noul)、[Choice 官方文件](https://docs.typesafe.ai/primitives/choice)。門檻、五個動機與備援行為屬這份範本的設計。

## 3. 找到 Jev 看到的資料（25 分鐘）

匯出 JSON，打開第一筆 decision 的 rawTrace，找到第一階段 request.state。

核對：

1. board 有 20 列，每列 10 個字元；點代表空格。
2. current 與 next 分別是目前及接下來 5 個方塊。
3. features 包含高度、空洞、起伏與井深指標。
4. candidates 每筆包含 ID、旋轉、x/y、四格位置、落下後特徵與程式參考分數。
5. 第二、三階段逐步補入 senses、基準位置與 proposals。

模型取得的資料已由程式整理。練習回答：「如果移除候選結果，只給原始棋盤，模型還需要多做哪些工作？」

## 4. 對比兩個情境（25 分鐘）

比較「空白棋盤」與「生存挑戰」，各執行三次單步。這些數字是你這次預演的結果，請勿推廣成 Jev 模型能力結論。

記錄啟動動機、提案／獨特位置數、否決數、最終空洞和高度。寫下哪個現象符合你的預期，哪個需要回看原始紀錄。

選做：若有自己的有效金鑰，再用相同情境測試 Jev 即時。切換模式會重開一局，請先匯出舊紀錄。保留 API 失敗與用量，不把失敗回合排除後再宣稱完美成功。

## 5. 帶回自己的工作流程（25 分鐘）

把同樣結構套到一個低風險的情境，例如內容分類：

- 狀態：內容、來源與你定義的分類條件。
- 合法選項：固定分類名單，保留待人工處理的選項。
- 多個判斷：相關性、可理解性、是否需要補資料。
- 執行檢查：選項必須存在、內容版本一致、未知情況不能默認成功。
- 證據：保存輸入版本、判斷、最終動作與失敗原因。

這是課堂設計練習，沒有把專案擴充成內容分類器或自動發布工具。
